# RPL Anomaly-Based IDS: submission package

Report: `RPL_IDS_Analysis.pdf` (source `RPL_IDS_Analysis.tex`, figures in `img/`).

Reproduction of Farzaneh, Montazeri and Jamali, *An Anomaly-Based IDS for
Detecting Attacks in RPL-Based Internet of Things* (ICWR 2019), on Contiki-NG
v5.2 with Cooja, plus a fixed- versus sliding-window comparison.

## Requirements

Docker only. Everything else (Contiki-NG, Cooja, the cross-compilers, Java and
the Python analysis stack) is pinned inside the image.

## Running it

```bash
./run.sh build      # once, ~5 min: clones Contiki-NG v5.2, applies the patch, builds Cooja
./run.sh version    # print the recorded toolchain versions
./run.sh test       # 28 host-side tests, ~3 s
```

Reproduce the results in the report:

```bash
./run.sh matrix --preset paper --seeds 1 2 3 4 5 --modes paper sliding   # ~22 min
./run.sh matrix --preset dis-threshold --seeds 1 2 3 --modes paper --append
./run.sh matrix --preset rates --seeds 1 2 3 --modes paper sliding --append
./run.sh aggregate                 # per-configuration summary
./run.sh plot matrix               # figures into report/figures/
```

A single scenario, end to end:

```bash
./run.sh gen --nodes 20 --spacing 20 --seed 1 --attack dis --attackers 1 \
             --attack-period-ms 0 --attack-start 75 --attack-duration 0 \
             --duration 30 --out simulations/demo.csc
./run.sh sim simulations/demo.csc
./run.sh metrics logs/demo.log
```

## What is here

| Path | Contents |
|---|---|
| `Dockerfile`, `docker-compose.yml`, `run.sh` | pinned toolchain and the command wrapper |
| `firmware/` | root, node and the two attackers, plus `ids.c` (the detector) |
| `include/` | `ids.h` and the generated coefficient table |
| `patches/` | the two-line Contiki-NG hook, applied at image build time |
| `scripts/` | scenario generator, headless runner, parser, metrics, matrix driver, plots |
| `tests/` | 28 host-side tests, including a bit-exact firmware replay |
| `simulations/` | generated scenarios and their attacker ground-truth files |
| `results/` | `matrix.csv` (one row per run), `summary.csv`, overhead, repeatability, replay check |
| `report/` | report source, figures, kept evidence logs, demo script |

`logs/` and `firmware/build/` are omitted: both are regenerated by the commands
above, and together they exceed 700 MB. The kept logs the tests rely on are in
`report/evidence/`.

## Verification

`./run.sh test` runs the unit suite. `python scripts/replay_check.py` (inside
`./run.sh shell`) replays every stored log and re-derives each detector decision
from the logged counts, requiring an exact match. Cooja is deterministic per
seed, so any run regenerates byte-identically.
